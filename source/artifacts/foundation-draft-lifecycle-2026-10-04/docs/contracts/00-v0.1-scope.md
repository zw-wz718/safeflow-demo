# SafeFlow v0.1 实现范围

## 目标

第一版只证明一条确定性、安全、可恢复的模拟业务闭环。LLM不是第零步依赖，固定`PlanningResult`可以驱动全部合同测试。

## 固定假设

- 架构采用Rust模块化单体。
- PostgreSQL是任务、操作、幂等、许可和关键审计的真源。
- 第一条有副作用纵向链路是模拟转账，不连接真实银行或真实资金。
- 强验证先使用`MockAuth`；生产配置必须拒绝加载该实现。
- 软风险信号先计算和审计，不改变执行路径。
- 写操作不进行无条件自动重试。
- 金额使用十进制定点语义，进入合同层后以规范字符串表示。

## 安全不变量

1. LLM、客户端和Tool不能指定可信用户身份。
2. 没有`READY_TO_EXECUTE`裁决就不能签发写操作Permit。
3. 没有数据库中有效且绑定当前指纹的Permit就不能提交写操作。
4. 提交结果未知时禁止重新提交，只能按原业务操作编号查单。
5. Tool、Policy、Schema和最低安全等级缺少任意一项时Fail Closed。
6. 业务状态、Permit消费、幂等记录和关键审计不得出现部分提交。
7. 原始ToolResult、密钥、验证码和未脱敏业务数据不得进入LLM上下文。

## 非目标

- 多Agent、多模型路由和自主反思。
- 自动修改或发布Prompt、Policy和权重。
- 生产级真实认证、真实短信或真实银行适配器。
- 微服务拆分、跨库事务和外部可信存证。
